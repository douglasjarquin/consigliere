Architecture

One boss, one consigliere, autonomous soldiers in isolated herdr worktrees, and a thin harness layer that speaks codex and claude natively.

The three roles

bossYou. The only one who lands work. Every PR comes back for your word.
consigliereThe root session: codex or claude launched in this repo with AGENTS.md loaded. It dispatches, supervises, and lands. It never writes to a project itself.
soldierAn autonomous agent spawned into its own herdr workspace, one per task. Soldiers inherit the root session’s harness.
capoA persistent, provisioned helper on the machine-local roster in host/. See the capo-provisioning skill.

What replaced what

Consigliere is a from-scratch rewrite of Firstmate, built for two harnesses and one terminal runtime, leaning on their native features instead of generic multi-backend shims.

worktreesherdr-native worktrees (workspace-per-task) replace the treehouse pool
statusherdr-native agent status replaces pane-regex busy detection
harnessone thin harness layer, bin/cs-harness-lib.sh
supervisionone supervision protocol (bounded foreground checkpoint), one Stop-hook backstop
size~9k lines of bash instead of firstmate’s ~29k

Harness detection

The root harness is auto-detected: CLAUDECODE=1 ⇒ claude, else codex. host/harness.conf overrides. AGENTS.md is the always-loaded operating contract; claude loads it via the CLAUDE.md symlink.

Session start

The session starts with bin/cs-session-start.sh, which prints one ordered digest of the whole operating picture. Its header owns the section order and contents. It reads the same required/optional inventory and version floors as bin/cs-doctor.sh.

Repository layout

bin/cs-* scripts; read each header before first use
skills/agent-loaded procedures: afk, rundown, the-books, vault, capo-provisioning, upstream-review, …
docs/architecture, configuration schema (owner), supervision protocol, agent lifecycle control, optional turn telemetry, verified herdr/codex/claude/lavish/codegraph facts
tests/colocated behavior tests: bash tests/<name>.test.sh or bin/cs-test-run.sh --portable
config/user-owned tree (settings and durable memory); boss-private, gitignored; back it up wholesale
host/machine-local sibling: capo roster, harness pin, activation; never backed up
data/ state/ projects/generated output, volatile runtime state, clones; disposable or re-creatable
grokbot/vendored, pinned port of grok-ship for the Grok Bot platform

Backup and restore

back up:      cp -a <home>/config <backup>/          # no exclusions
new machine:  cp -a <backup>/config <newhome>/config
              then fill in host/ for this machine and run bin/cs-doctor.sh
