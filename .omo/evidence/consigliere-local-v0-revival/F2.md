## Invariants checked

SQLite remains authoritative for durable state, while Git, filesystem, process, network, and Codex operations occur outside SQLite writer transactions through durable intent and reconciliation.

Project, Mission, Attempt, Workspace, lease, generation, fence, runner identity, invocation, and exact Git SHA identities are checked at each external boundary.

Home locking uses the kernel-managed lock before migrations, cleanup, listeners, schedulers, reconciliation, or runner startup.

Boss authority, Attempt capability authority, runner control authentication, model advisory authority, and delivery authority remain separate.

Dispatch has one recoverable Attempt slot, progression waits for verified runner death, and imported work is bound to one exact result ref.

Codex execution uses bounded fresh context and bounded usage records without native transcript resume or full transcript retention.

Verification commands are literal argv arrays with bounded count, timeout, environment, cwd, and output.

The new progression regression closes the previously observed gap where an ignored `AttemptResults.mark/3` error could leave an external result ref after a failed durable checkpoint.

The fixed code propagates terminal-sequence, death-verification, commit-verification, and imported-status persistence errors and stops before external import when the checkpoint cannot be recorded.

The verification child process now starts through `env -i` with only the explicit allowlisted environment, so an unlisted parent secret cannot cross into Project-configured commands.

Structured redaction now covers quoted token-like keys and `CS_CAPABILITY` without an unbounded key-matching expression, so oversized non-secret ContextPacks remain bounded.

Termination no longer trusts a persisted PGID by itself; it requires canonical inventory, matching Attempt identity and fence, verified runner liveness, and a matching persisted PGID before signaling.

Live inventory additionally requires the observed runner and harness PIDs to be members of the manifest's recorded process group, so a stale same-host process cannot make a live group appear verified.

Checkpoint import applies the complete trusted-workspace verifier before any external fetch, including exact HEAD, alternates, remotes, credential helpers, hooks, permissions, and shared-object checks.

The Attempt capability visible to the worker is the short-lived worker-scoped credential required by task #132, while the runner control-channel secret remains separate and private.

The harness environment now receives no daemon API socket or reusable Attempt capability; the trusted runner retains the reporting capability and forwards only bounded reports through the bridge.

Pause revokes live capabilities without rotating the persisted fence before the runner manifest is reconciled, so the live manifest remains bound to the Attempt during verified termination.

An explicit durable `pausing` blocker causes the MissionCoordinator to retry settlement on refresh, including after runner `DOWN` and daemon reconstruction, without pausing unrelated active Missions.

Redaction covers bounded compound secret assignments, private-key fields, and PEM blocks in addition to the existing token-shaped keys and sensitive structured values.

Provider-prefixed `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` assignments are covered by the same fixed-family redaction path, and authenticated harness stderr is retained in the bounded Attempt log.

Runner stdout is assembled by complete newline-delimited records across transport chunks, with an explicit bounded discard path for oversized unterminated records.

Result idempotency compares the persisted `accepted_terminal_sequence`, so a changed terminal event cannot be accepted as a duplicate of an earlier report.

Unverified runner death holds the durable dispatch slot across scheduler restart until an independent death verification releases it.

Dispatch re-reads an Attempt after a stale spawn transition instead of crashing the MissionCoordinator or creating a second Attempt.

Protocol-failure termination is classified from both the persisted Attempt marker and the GenServer stop reason, preserving a semantic failure instead of downgrading it to `lost`.

The non-sandboxed SQLite test suite runs with one case at a time, and process-level report fixtures explicitly prepare their trusted workspace and trap the expected linked failure exit.
